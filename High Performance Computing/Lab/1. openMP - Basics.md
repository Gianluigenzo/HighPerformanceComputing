### Exercise 1 - 'Parallel' Pragma
Simple exercise made to explore the usage and functionality of `#pragma omp parallel` and a few other constructs.
- exercise1.c
```C
void exercise(){
	int tid = 0, nthreads = 0;
	printf("I am thread number %d out of %d!\n", tif, nthreads);
}
```

The objective is to simply create a parallel section, with the desired number of threads, inside of this function. Then, using `omp_get_thread_num()` and `omp_get_num_threads()`, get to know the execution order for the team of threads that executes `print()`.

- **Solution**
```C
void exercise(){
	#pragma omp parallel num_threads(NTHREADS)
	{
		int tid = omp_get_thread_num(); 
		int nthreads = omp_get_num_threads();
		printf("I am thread number %d out of %d!\n", tif, nthreads);
	}
}
```

>[!Note]
>`NTHREADS` is a macro defined at compile time. Compilation happens via Makefile with the following command: `make EXERCISE=exercise1.c EXT_CFLAGS="-DNTHREADS=4" clean all run`.

### Exercise 2 - Loop parallelization
Usage of `#pragma omp for` directive and `#pragma omp schedule(...)` clause.

All the following sub-exercises start from the same for loop:
```C
for(int i = 0; i < NITERS; i++){
	work(W);
}
```

In the previous exercise `#pragma omp parallel` was used to create a parallel section for a certain section of code, this meant that the section was replicated for each thread and the code executed `NTHREADS` times. To achieve a `for` loop parallelization in the sense that the `NITERS` are divided among all the working threads, the `#pragma omp for` directive is needed:
```C
#pragma omp parallel for num_threads(NTHREADS)
for(int i = 0; i < NITERS; i++){
	work(W);
}
```

Starting from this result, the next exercises will exploit different modes of the `schedule(static)` clause to achieve different execution results.
#### Exercise 2a - Static Loops
Use of `schedule(static)`:
```C
#pragma omp parallel for num_threads(NTHREADS) schedule(static)
for(int i = 0; i < NITERS; i++){
	work(W);
} // implicit barrier (could be specified with #pragma omp barrier)
```
![[openmp-basics-2a-spec1.png|281]] Assuming $NITERS = 16$.

`schedule(static)` is optimal if the workload is balanced between each iteration, as there's a very little overhead (the scheduling is computed only once when reaching the `for` loop). Each thread will execute $M = \frac{NITERS}{NTHREADS}$ iterations.
#### Exercise 2b - Dynamic Loops
Use of `schedule(dynamic, CHUNK_SIZE)`:
```C
#pragma omp parallel for num_threads(NTHREADS) schedule(dynamic, M)
for(int i = 0; i < NITERS; i++){
	work(W);
} // implicit barrier (could be specified with #pragma omp barrier)
```

`schedule()` clause with `dynamic` requires the specification of an additional parameter which is the chunk size $M$, better explained as the number of iteration each thread will execute before checking again how main iterations are left to do. An overhead will be present before *AND* after $M$ iterations:
![[openmp-basics-2b-spec1.png|320]] ![[openmp-basics-2b-spec2.png|320]]

Still assuming $NITERS = 16$; the two images show the usage of `schedule(dynamic, M)`, with $M = \frac{NITERS}{NTHREADS}$ and $M = 1$ respectively.
- The first one produces the same effect of using `schedule(static)` except for the second overhead at the end of the $M$ iterations; 
- The second one shows the finest granularity possible with `schedule(dynamic, M)`.
Clearly these two examples are of use for this case of balanced workload.

### Exercise 3 - Work Balancing
Same as the previous exercise, but with different workloads at each iteration.
```C
#pragma omp parallel for num_threads(NTHREADS)
for(int i = 0; i < NITERS; i++){
	work((i>>2) * W);
}
```

![[openmp-basics-3-spec1.png|320]] ![[openmp-basics-3-spec2.png|320]]

The images above show the same two examples seen previously with $M = \frac{NITERS}{NTHREADS}$ and $M = 1$ respectively.
It's easily observable how the first one produces a huge amount of idle time for threads T1, T2 and T3, while the second one, despite the increased number of overheads, is able to achieve a noticeable speedup by transferring iteration $\#15$ of the loop on T1.
